# Performance redesign verification

Date: 2026-10-06. Implementation branch: `performance/preserve-format`.

## Implemented behavior

- Default output preserves each detected source format, including mixed batches. JPEG downloads preserve `.jpg`/`.jpeg`. Explicit conversion cannot revert to another format through the size guard.
- Native bitmap-to-Canvas JPEG/WebP encoding performs one preset encode without full-image RGBA extraction or perceptual scoring. The UI does not claim a measured quality score for that route.
- Existing PNGs up to 4 MP use direct single-thread OxiPNG optimization at level 1 when no transform is requested. Larger PNGs stream validated filtered scanlines through native deflate inflation and fflate level-1 compression, avoiding full RGBA decoding. Bit depth, transparency, interlacing and decoded pixels remain unchanged. Compression has a four-second elapsed effort budget checked between bounded chunks; inflation validation continues even after effort runs out. If recompression grows the data or exhausts the effort budget, the complete sanitized original is retained. Lossless JPEG retains compressed pixels with safe metadata handling and minimal orientation metadata when necessary.
- Global admission reserves estimated processing memory before full file reads; the 512 MiB estimate budget and two-job cap span overlapping submissions and worker previews. Large jobs run alone. Workers are lazy, terminate on completion/cancellation/failure, and have a 30-second deadline.
- Thumbnails are 96-pixel worker previews; comparison previews are capped at 1600 pixels. Preview work is cancellable, serialized behind processing, and has a 15-second deadline.
- OPFS stores result files under a 256 MiB per-tab repository limit. In-memory fallback is capped at 64 MiB. Downloads read Blobs/Files; ZIP uses 1 MiB chunks with disk-write backpressure and a 64 MiB fallback cap.
- GIF color maps are bounded; ICC scratch buffers use tiles; SVG/HEIC resources are disposed. Unsupported TIFF pages/bit depths reject conversion. Failed WASM compilation is retryable and streaming fallback has an unconsumed response.
- PNG uses the explicit single-thread OxiPNG binding. Production-browser checks exposed the wrapper selecting Rayon with a single-thread binary; bypassing that wrapper also prevents unmanaged CPU-count subworker spawning.
- AVIF encoding likewise uses the explicit single-thread binding paired with its shipped binary, rather than automatically selecting a multithreaded wrapper. Advanced-format effort is bounded.
- Narrow store subscriptions and memoized rows avoid unrelated result updates rerendering every component. Initial JS, individual workers, and individual WASM files have separate bundle checks.
- WebKit diagnostics exposed COEP-blocked repeat worker loads: Vite's preview static server returns 304 responses before applying its configured headers. Preview middleware now applies security headers before the static handler, including on conditional responses. Development, preview and production headers explicitly include `Cross-Origin-Resource-Policy: same-origin`, retaining strict COOP/COEP/CSP. Hashed production assets use immutable caching; HTML does not. Browser checks cover conditional response headers, repeated processing workers and comparison previews. [WebKit's cache/COEP issue history](https://bugs.webkit.org/show_bug.cgi?id=245346) informed the investigation; local worker errors and Vite's response path established the cause here.
- Keyboard menu selection ignores stationary pointer events generated by scrolling, preventing WebKit from replacing the highlighted keyboard option with a hover state.

## Recorded 32 MP benchmark

Command: `node scripts/benchmark-large-image.mjs`, after `pnpm build` and with `pnpm dev` running. The harness loads the production pipeline worker and its production chunks; the main-thread pool harness is served by Vite. Each run starts a fresh worker. This measures worker initialization plus processing, not full upload-to-preview latency.

Reference environment: Linux, Intel Core i5-8250U at 1.60 GHz, Node 22.23.2, Playwright headless Chromium. Input is a deterministic synthetic 7372×4392 JPEG with gradient and translucent texture, encoded at 0.97 quality. It is not the user's file and does not establish photographic fidelity.

| Run | Worker wall time | Pipeline time | Output          |
| --- | ---------------: | ------------: | --------------- |
| 1   |          4846 ms |       4258 ms | JPEG, 7372×4392 |
| 2   |          2131 ms |       2011 ms | JPEG, 7372×4392 |
| 3   |          2532 ms |       2381 ms | JPEG, 7372×4392 |

Input: 7,734,717 bytes. Output: 2,712,680 bytes at quality 80; rounded size reduction 65%. Compression ratio is fixture-specific and is not a comparison against Compresso's 17% result.

Summed Chromium process-tree PSS sampled every 100 ms: baseline 143 MiB, peak 584 MiB, increment 441 MiB. Includes fixture generation and output validation. These are sampled process measurements, not a hard memory ceiling or proof that all devices remain below 512 MiB. Three samples cannot establish p95 latency.

### Large PNG effort-budget result

The same deterministic canvas fixture encoded as PNG is 34,158,290 bytes. Before the effort budget, its production worker exceeded the 30-second deadline. With the four-second compression effort budget, all three fresh workers completed and returned a complete PNG at the original 7372×4392 dimensions:

| Run | Worker wall time | Pipeline time | Output bytes | Reduction |
| --- | ---------------: | ------------: | -----------: | --------: |
| 1   |          6645 ms |       6441 ms |   34,158,290 |        0% |
| 2   |         14252 ms |      13645 ms |   34,158,290 |        0% |
| 3   |         14515 ms |      13776 ms |   34,158,290 |        0% |

The budget governs compression effort, not total processing latency: CRC checks, native inflation validation and worker startup still cost time. All three runs retained the original compressed image after effort exhaustion. This prevents the former expensive recompression timeout, but does **not** establish competitor-grade large-PNG compression. A faster native/WASM deflate implementation remains necessary to improve this difficult fixture without relaxing pixel preservation. No universal 4–5 second or 17% reduction claim is justified.

Summed Chromium process-tree PSS: baseline 111 MiB, peak 481 MiB, increment 370 MiB, including generation and output validation. PNG and JPEG measurements ran serially after build/tests/browser checks ended. The input is synthetic; the original reported file was unavailable.

## Remaining scope and limits

- Browser-native JPEG/WebP output and color handling can differ by browser. Quality 80 is a preset, not a perceptual quality guarantee; users should compare important images.
- PNG, AVIF, GIF conversion, and other WASM routes have separate speed/memory characteristics. They do not inherit the JPEG benchmark. Estimates and worker termination bound admission and duration, but native/WASM allocators are not governed by an exact byte limiter.
- Animation remains unsupported. JPEG XL inputs reject before decode until safe dimension inspection exists. HEIC, SVG, TIFF, BMP, and GIF preserve routes retain safely when possible or explain unsupported processing when requested privacy/transforms cannot be honored. There is no new same-format HEIC encoder, vector SVG optimizer, or compressed-domain JPEG optimizer.
- Comparison zoom scales the bounded display preview; full-resolution detail inspection remains future work. Result list virtualization is deferred at the current 100-file limit.
- ZIP temporary files live for up to two minutes to support downloads. Disk quotas can reject export; completed image results remain available for individual downloads.
- No production deployment, push, or merge was performed. The exact reported crash requires the original file/device to reproduce.
